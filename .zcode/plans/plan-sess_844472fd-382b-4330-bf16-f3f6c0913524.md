# ai-app-portal「AI应用门户」M1 开发计划

## 一、范围与选型（已确认）

- **范围**：M1（门户可用）拆解到工作包级；M2–M4 给模块级路线图，M1 交付后再细化。
- **技术栈**：pnpm monorepo；服务端 **Express 4 + TypeScript**（Node ≥22，最大化移植 office-tool 已验证代码）；前端 **React 18 + Vite + TS**（Ant Design 5，token 与 CSS variables 主题联动）；数据层 **Drizzle ORM**（better-sqlite3 起步，为 FPK 的飞牛 DB 预留 mysql2 方言）；关键依赖：`acme-client`（B3）、`@simplewebauthn`（A3）、`otplib`（TOTP）、`nodemailer`（SMTP 验证码通道）。
- **参考实现**：office-tool（同工作区）按下表移植，剥除一切单位指纹（`X-Office-*` 头更名 `X-AAP-*`、cugb 主题不进新库）。

## 四、M1 工作分解（按依赖序，含验收）

**W0 规范契约先行（~1.5d，可与 W1 并行）**——把本次新增的三项要求落成契约文档，先于实现冻结接口：
- 更新 `app-develop.skill-v0.1.md` → v0.2（给包作者的契约）：① **Python 日志规范**：统一用平台注入的 logging handler（`aap.log.debug/info/warning/error` 糖 + 标准 logging 兼容），四级语义与示例；**开发日志（本地调试/试运行）与运行日志（线上调用）全部经沙箱结构化通道收口进 portal 运行记录**，不得旁路（无自建文件/网络日志出口）；脱敏（不打密钥/个人数据原文）与量限制（单次运行日志条数/字节上限）；本地调试沙箱用法。② **统一页面元素**：persistent 应用由平台自动注入「返回个人中心 / 退出登录」统一跳转按钮，包作者约定不得遮挡/覆盖、右上留空间；HTML 工具嵌在门户 shell 里天然携带，无需处理。
- 同步更新 `app-develop-internal.skill.md`（平台内部实现约定）：沙箱日志管线（结构化 JSON on stderr → supervisor 捕获 → portal 运行日志表，DEBUG 仅调试/试运行保留，线上 INFO+ 按保留期清理）；**调试沙箱 = 生产同一代码路径 + 调试开关**原则（禁止另写模拟器造成行为漂移）；chrome 注入机制与手动 include 转义；`aap` 对象接口冻结原则（接口先定，mock 实现与生产实现行为一致）。

**W1 骨架与基建（~3d）**：monorepo + TS/ESLint/vitest；server：config、drizzle 首批迁移（settings/audit/sessions/users）、`/api/health`、安全响应头、错误处理；web：Vite 骨架、路由、主题 CSS variables token 契约 + AntD5 联动。
验收：`pnpm dev` 一键起前后端；主题切换 demo。

**W2 安全内核移植（~4d）**：上表 lib/* 移植 + 对照 office-tool 行为的单元测试；CSRF Origin；`req._clientIp`；统一审计事件常量。
验收：会话/封禁倍增/PoW/审计测试全绿。

**W3 账号与注册 A2（~5d）**：
- 统一 `users` 表（kind 列，M1 全 'local'；M2 OIDC 共表，刻意消除参考实现双表 uid 串号面；身份头仍按 (kind,uid) 契约）+ `local_credentials`。
- 注册开关三档（关/开/开+邀请码，默认关）；`CodeChannel` 抽象 + SMTP adapter（SMS adapter 留接口）；验证码 6 位/5min/同通道 60s 限 1 + 24h 上限/哈希存储单次有效；注册/找回/绑定三入口全挂 PoW + 可选 Turnstile（后台填 key 即启用）；同 IP 24h ≤5 号；废弃注册 N 天清理；首账号自动 admin。
验收：三档开关、验证码限发、邀请码、防爆破联测通过。

**W4 MFA A3（~6d，全新构建）**：TOTP（RFC 6238 ±1 窗口、重放拒绝、QR provisioning、10 枚恢复码 scrypt 哈希用一枚废一枚）+ Passkey（@simplewebauthn，二次因子与无密码主登录双角色、多凭据、signCount 克隆检测）；登录状态机 `password_ok → mfa_pending（低权，仅限 MFA 端点）→ full`；敏感操作步升认证（5min TTL）；策略：admin 强制不可关、会员默认强制（M3 接入）、普通可选；全事件审计。
验收：TOTP/Passkey/恢复码/步升/状态机测试全绿。

**W5 应用网关 B1/B2/B4（~7d，最大风险项）**：apps 表（id/名称/图标/upstream/访问策略三态 公开|登录|会员/passUser/排序）+ 管理端 CRUD 热生效；urlSecret 加密落盘；proxy.ts 移植 + 门禁挂钩；**WebSocket 自研**：HTTP 与 HTTPS 双 server 挂 `upgrade` → `/app/<id>/` 前缀匹配 → 裸 req 解析 sid cookie 查会话（session 哈希逻辑裸 req 版）→ 三态门禁 → TCP 双向管道（移植 office-tool 的 101 手写 + 双向 error 互毁）；SSE 验证零缓冲；令牌桶双维度限流。
验收：Dify/Streamlit 样例应用经 `/app/<id>/` 可用；WS 聊天（HTTP 与 HTTPS）不卡；路径穿越/越权用例全拒。

**W6 自动 HTTPS B3（~4d）**：acme-client HTTP-01（账户密钥持久化、订单/挑战、证书落盘 data/tls、到期前 30 天续期、失败重试与状态上报供仪表卡）；PEM 手动上传热替换兜底；HTTP→HTTPS 跳转开关；纯门户模式（不启 TLS，反代外置）。

## 五、M2–M4 路线图（模块级）

- **M2 LLM 网关（C1–C6）+ OIDC（A5）**：`/v1/chat/completions`（含流式）+ `/v1/models`；网关 app-token（注册下发/吊销/限额，真实上游 key 永不下发）；多上游配置 + 模型目录聚合；同模型 failover/健康检查/轮询加权；应用级+用户级（passUser 归因）双粒度计量，append-only 用量流水（只记不判）；C6 预检闸门 + 与 D 的缓存失效协议（进程内事件总线）本期定接口；流式不中途掐断、事后校正。移植 oidc.js + PKCE + (kind,uid) 契约。
- **M3 计费（D1–D4）**：会员×应用可见性（打通 W5 三态门禁的会员分支）；token 充值池+模型倍率定价（管理员定价）；D2a 结算引擎（异步消费流水、欠费态）+ D2b 缓存同步三触发（扣款/充值/手动调额）；支付渠道 adapter（首发渠道届时定）；运营面板（余额排行/应用热度/成本毛利）。
- **M4 生态（G1–G5）**：
  - **`packages/aap-sdk`（Python，核心交付）**：`aap` 运行时存根（llm/db/storage/http/log）+ **`aap-dev` 本地调试沙箱 CLI**。一致性策略：调试沙箱与生产沙箱**共享同一实现代码路径**（同一镜像、invoked/persistent 双模式同路径），调试模式只是开关（env `AAP_DEBUG=1`）+ 详细日志全开：每次 SDK 调用（入参/出参/耗时）、LLM usage、HTTP 代理逐请求（URL/白名单判定/状态/耗时）、SQL 语句、storage 操作、进程生命周期（启动/超时/退出码）全量打印到终端并可选 `--submit` 回传 portal。LLM 在本地可切 mock（回声/夹具）或真实网关 dev token；域名白名单在调试下照常强制执行（行为一致），夹具 mock 可绕过外呼但不绕过白名单校验。
  - **日志收口管线**：沙箱进程唯一日志出口 = 结构化 JSON（stderr lines）→ 平台 supervisor 捕获 → 运行记录表（谁/哪个包/耗时/token/日志）；个人工具运行记录页与管理端审核页试运行均可看；DEBUG 级仅调试/试运行保留，线上 INFO+ 按保留期清理；量限制与脱敏按 W0 契约执行。
  - **统一 chrome 注入**：persistent 应用 HTML 响应自动注入「返回个人中心/退出登录」统一按钮（复用 B1 HTML 注入机制，失败静默不阻断），符合 W0 契约。
  - 其余 G1/G3/G4：.neon-aap 包格式与校验（manifest 能力声明）、可见性三态与审核流（看码/试运行/通过驳回）、生命周期（版本重审/举报/下架/ed25519 预留）。样例包按 v0.2 规范产出并走通「造工具→自用→审核上架」。

## 六、关键设计决策与风险

1. **WebSocket 是最大自研缺口**：office-tool 只有独立端口单上游透传且 HTTPS 下 WS 不工作；W5 的「双 server upgrade + 路径匹配 + 裸 req 会话鉴权」为新代码，需样例应用实测（Dify/Streamlit 聊天都依赖）。
2. **ACME 受网络环境约束**：HTTP-01 要求 80 端口公网可达；内网 NAS 用户走 PEM 兜底或纯门户模式，向导明确引导，不让 ACME 失败堵死首配。
3. **反代安全权衡照搬并文档化**：剥上游 CSP/XFO + 同源 iframe = 上游 JS 可带门户 cookie 调门户 API（仅嵌入可信应用）；请求侧剥 cookie/authorization、响应剥 set-cookie 照旧。
4. **统一 users 表**是相对 office-tool 双表的刻意改进，M2 OIDC 共表后彻底消除串号面；身份头 (kind,uid) 对外契约不变。
5. **调试沙箱一致性**：铁律是「同一代码路径 + 开关」，绝不另写并行模拟器；`aap` 接口在 W0 冻结，M4 实装时 mock 与生产实现对照同一测试集验证行为一致。
6. **FPK 是外部依赖**：fnnas-docs 调研+真机验证有不确定性，排最后且不阻塞 M1 其他出口项；Docker 形态先行。
7. **Drizzle 迁移纪律**：M1–M4 持续加表，禁手改已发布迁移，一律 drizzle-kit generate。
8. **单位指纹零进入**：X-Office-*、cugb、校色校徽不进新库；品牌默认纯净（D6）。
