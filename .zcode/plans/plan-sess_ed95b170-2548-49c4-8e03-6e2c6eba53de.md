# test.xext.top 授权渗透测试计划（公网信道 · 灰盒）

## 目标与交战规则
- **目标**：https://test.xext.top（47.82.98.164，仅 80/443 公网信道；不碰 SSH/DB/日志等主机侧信道）。
- **攻击姿态**：① 未认证公网访客；② 自注册低权限用户。源码仅用于定位漏洞（灰盒），全部结论以公网实测复现为准。
- **admin API 仅用于搭建测试夹具**（必要时开注册/建测试账号 A=攻击者、B=受害者），不作为攻击手段；不对 admin 会话/MFA 做任何攻击。
- **禁止**：DoS/资源耗尽（zip 炸弹、15MB 匿名 JSON flood 只作代码层记录，不实测）；删除/篡改服务器既有数据；留任何持久化痕迹。并发竞态测试短暂并发 ≤50，请求总量克制。
- **沙箱取证（只读）**：允许 run 的探查代码读 `app.db`、确认 `master.key` 存在、探测 127.0.0.1 沙箱端口并演示跨沙箱访问、回显注入 env；证据只写进报告，不落 webshell、不修改文件。

## 阶段 0：基线与夹具
- curl/openssl 基线：证书链、TLS、安全头（CSP 无 script-src 实证）、cookie 标志（Secure/HttpOnly/SameSite）、HTTPS 302 行为与 Host 反射。
- `/api/portal/bootstrap`、`/api/health`、`/api/dev/guide`、`/api/dev/docs` 信息泄露确认。
- 经 admin API 确保可注册（或直建账号），创建测试账号 A、B，登记所有测试产物。

## 阶段 1：未认证攻击面
1. **404 反射 XSS**：`GET /app/%3Cimg src=x onerror=…%3E/x` → 浏览器验证执行；演示注入脚本可调 `/api/auth/me` 等（用 B 会话证明会话劫持面）。
2. **admin 面一致性**：低权/匿名探测全部 `/api/admin/*`，重点验证 `/api/admin/redeem/*` 当前是否仅靠 adminRouter 挂载顺序偶然挡住（agent3 发现的脆弱守卫）。
3. `/v1` Bearer 猜测无节流（少量请求确认 401 无锁定无日志告警）；注册/找回验证码步骤无 PoW 限速（对自注册流程少量猜码确认）。
4. 匿名 WS 握手到公开应用；302 跳转 Host 注入观测。

## 阶段 2：低权限用户攻击（账号 A）
1. **存储型 XSS**：A 上传 `display_name` 带 payload 的应用 → 登出访问 `/app/<id>/` 403 页触发；浏览器演示同源任意 API 调用能力。
2. **跨应用前缀读**：A/B 各建前缀重叠应用，`GET /app/aa/..%2F<兄弟>%2Fapp.sqlite` 验证 200 泄露。
3. **egress SSRF**：A 的应用 manifest `network` 声明 `169.254.169.254.nip.io`、`metadata.aliyun.com`、`127.0.0.1.nip.io` → `POST /api/aap/egress` 读响应体（阿里云元数据/本机端口）；错误消息做内网端口 oracle。
4. **沙箱代码执行取证**（按只读范围）：上传 mod.py → run → 回显 DATA_DIR 列表、app.db 可读性、master.key、127.0.0.1 端口探测、env（AAP_TOKEN/AAP_PLATFORM）；顺带验证 **Host 头投毒**（`Host: evil…` 时 AAP_PLATFORM 被污染）与 `manifest.entry` 路径穿越。
5. **LLM 网关无 ACL/无归因**：用 A 的 app token 直调 `/v1/models` + `/v1/chat/completions`，无身份头观察全模型可用性与不计费（若上游未配则记录为配置依赖）。
6. **审核状态绕过**：应用更新后 reviewStatus=pending 但内容立即生效的实测。
7. **_submit_tmp 竞态**：A/B 并发提交同名条目包 ≤50 次，检查落盘串包。
8. **redeem/billing**：限速边界（10/min）确认；admin 造码后 A 并发双兑验证事务化；兑码状态 oracle 记录。
9. **MFA 步升缺失**：A 演示 enroll 无需 step-up（劫持会话持久化路径）。
